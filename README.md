# ElevenLabs Scribe v2 Dictation — working notes

Personal notes on this app: what it is, for debugging and development purposes. 

Goal is to create a web-only, dependency-free, highly accurate dictation tool that provides for short-form voice typing/dictation. The ideal use case is dictating clinical documentation, with domain specific prompting, focus on latency, and ability to work despite limitations of sandboxed/firewalled corporate environments. At this time, a cloudflare worker/DO serve at the edge and act as a go-between to ElevenLabs Scribe V2 API. 

Ideal Use: 
  -high quality microphone, installed to desktop as a PWA, and use autohotkey script to focus the window and activate dictation. Auto copy to clipboard, and then additional hotkey to paste into desired focused field. 

Phone dictation:
  -Using a QR or pairing code, link phone to same cloudflare worker, transmit audio to Elevenlabs via the worker, and then to the desktop where it can then enter the regular dictation workflow.
  -Primary drawback is IOS microphone permission/wedging issue that is seemingly insurmountable. This is an intrinsic limitation of PWAs in IOS. 
  -Workaround would be android or a device solely used for dictation that could be placed in focus mode.

Learnings so far:
  -Goal was a batch/realtime hybrid; where the realtime feedback would be backed up by a concurrent batch job that would be sent at the end of utterance. In practice, realtime transcription is not quite there. Attempted Soniox, ElevenLabs, Mistral. Soniox is close, but latency and accuracy issues were pervasive and      not fixable.
  -To me however, this represents the gold standard of dictation software. Seamless dictation, with high accuracy, minimal latency, all going to the cursor in real time, with the backup of the high domain-specific accuracy of a batch "recheck" at the end of utterance.
  -Realtime dictation products are close, but the multiple moving parts involved are a real last mile hurdle that is insurmountable at this time in this context.

## What it does

Hold a key, speak, release. The audio uploads to ElevenLabs Scribe v2 Medical (batch) and the transcript lands on the clipboard. Batch-only, medical config. The upload happens when you let go; Chrome/Edge can instead stream it while you are still talking (Diagnostics → "Upload while you dictate", off by default). If the server can't be reached the app says so while you dictate, sends the recording again once it can, and transcribes a failed long take into your notes by itself.

- **Pick the service, with an automatic backup.** Options → **Transcription service** chooses who transcribes: ElevenLabs Scribe v2 Medical (default), Soniox, OpenAI **gpt-transcribe**, or Mistral **Voxtral Small Transcribe 3** — swap by hand if ElevenLabs is having a bad day. Advanced → **Backup when the service is slow or failing** (default Mistral Voxtral; Soniox if the server has no Mistral key) gets the same audio automatically when the main service returns an error or hasn't answered after a few seconds (4 s for ElevenLabs, which normally answers in under one); whichever good transcript comes back first is used. The status line says which service wrote a take ("Transcribed by Soniox — ElevenLabs had not answered after 4 s."), the note is tagged "via Soniox", and it's otherwise a normal success. Soniox, OpenAI and Mistral need their API key on the server (a service without one is greyed out). Only ElevenLabs uploads while you dictate; an OpenAI take is text only (no speaker filter, no incomplete-transcript check, no keyterms). Mistral gets your keyterms as its context bias (up to 100: your own terms first, then the checked lists) but is otherwise text only too.
- **Push-to-talk.** Ctrl+Space (tap = start/stop, hold = talk-and-release). F13/F14 also start/stop, for the AutoHotkey relay (CapsLock → F13/F14).
- **No noise gate (since 2026-11-21).** mic → gain → high-pass → recorder: everything the mic hears is recorded and uploaded. Other people's voices are the speaker filter's job.
- **Live capture feedback.** While recording, a green trace sweeps across a grid like a monitor lead, with a "Hearing you" light and a large timer, all on-device from the analyser. Nothing streams; it just proves the mic is live.
- **Every dictation is a note** (2026-11-22). The desktop shows the same notes list as the phone, newest first: each note is editable in place (click and type; saved when you click away, Esc reverts), and has **➕ Add to this** (the next dictation is added onto that note, the newest or any older one, and the whole note is copied), **Copy**, **Report** and delete (two clicks). Options → "Add each dictation to the newest note" keeps adding to the newest note. There is no separate box or "Last dictation" slot any more, and clicking a note never switches appending on. Diagnostics → "Delete all notes" clears the list.
- **Report a mistake.** "Report" on every note opens a small box: the word it missed or got wrong, and what went wrong. The word can go straight into my vocabulary so the next take gets it right. Reports from every device land in one cloud log (Cloudflare D1, kept 90 days, shared access code required) and are listed under Diagnostics → "Show sent reports". A report carries the note's text.

### Audio cues — meant to be used without watching the screen

| Sound | Meaning |
|---|---|
| Single beep | Recording started |
| Rising double beep | Copied to the clipboard |
| Long low beep | Failure — sentinel `##DICTATION_FAILED##` copied, or the clipboard write failed. Don't paste. |
| Three descending beeps | Dead-mic alarm — recording but no signal (~2.5 s in) |
| Two beeps | Warn — a degraded but usable outcome; verify before pasting |

Start/done beeps are optional (Options). Failure and warn alarms always play, and reuse the running audio context so they sound even in a background tab.

## What's worked

- **Batch is the product.** Fast and accurate, dead simple, no streaming jitter. The three-engine era was a distraction (see below).
- **Loud failure, everywhere.** The prime directive — a silent failure is wrong text in a chart. Sentinel on the clipboard, alarms that always play, a dead-mic watchdog, and the last 100 transcripts kept in History so a botched copy is never a lost dictation.
- **One analyser, read-only.** The same level reading drives the trace, the "Hearing you" light, the dead-mic watchdog, the speaker filter's loudness pick and the incomplete-transcript check — and none of it can cut audio from the recording.
- **Phone link durability.** The phone dictates and the text lands on the desktop clipboard. The delivery is queued on the phone (persisted, retried on reconnect and at boot), acked by listener count, replayed by the room, and deduped by id — so a dropped link, or a phone that dies after transcribing, recovers instead of losing the note.
- **Keeping the phone screen awake.** The real fix for "iOS keeps killing the mic between takes" was to *prevent* the interruption (hold the wake lock while the phone is on its phone layout), not just recover after it.
- **Diarization keep-primary-speaker.** Drops a bystander voice the mic caught and reports how many words it removed. On by default on every device (Options → "Filter out other speakers"; since 2026-11-21 a desktop no longer needs its own opt-in). **It keeps the voice that is clearly loudest at the mic** (at least 2×, about 6 dB, louder than every other — the app measures the mic level every 30 ms and lines it up with each word's timing), however few words that voice said. If loudness can't tell the voices apart, it keeps whoever said the most, but only when one voice clearly dominates (so it never deletes my own words on an even split) — and any cut made that way warns. A big cut warns too. Every cut keeps what was heard before it: History and the phone notes show "Other voices were removed — show what was heard before the cut", with Copy unfiltered. It can never empty a clean note. ElevenLabs and Soniox label speakers; a take written by OpenAI or Mistral (including the Mistral backup) is not filtered.

## What hasn't worked (and the lessons)

- **Realtime/hybrid streaming — removed.** A lot of work, and our live feed stayed jittery while the same engine was smooth on the vendor's own demo. Root cause: we captured raw PCM and downsampled/sent it on the *main thread*, so under render load it shipped jittery audio; batch (and the demo) use off-thread `MediaRecorder`. Batch was always flawless, so I cut realtime entirely. Full post-mortem and a resurrection path are in [`REALTIME_HANDOFF.md`](REALTIME_HANDOFF.md) — I haven't given up on it.
- **The hidden append time window.** Append used to depend on how many seconds had passed since the last dictation — the same action gave different results, and a pause past the cliff silently wiped a note. Deleted; append is now purely explicit.
- **Picking "me" by word count.** The speaker filter used to keep whichever voice said the most. A short dictation ("negative for chest pain") next to a long conversation lost: the conversation was kept, my 4 words were dropped, and because they were under 15 % of the take it was a clean Done!. Loudness picks now (I'm the one at the mic), and a cut the loudness didn't confirm always warns. The unfiltered text was also being saved only on big cuts and never shown anywhere; now it's kept on every cut and visible in History.
- **Noise suppression / Voice Isolation don't stop other *voices*.** They strip *noise*; another person's speech is speech and survives them. The levers that actually work: hold the mic close (the biggest one), iOS Voice Isolation for noise, and the diarization filter for a second speaker. The one-time Mic tips card walks through them.
- **iOS hands back dead microphones.** After backgrounding, iOS leaves a dead mic track reporting `readyState:"live"`, unmuted, with no `ended` event — so the app trusted a corpse and recorded silence (the worst real bug: looked like it was recording, captured nothing). Fix: any backgrounding marks the graph suspect and forces a fresh `getUserMedia`. But iOS also reclaims the audio session with **no event at all** (Low Power Mode, an idle gap), leaving nothing to flag the corpse — so on the phone the press now reads the analyser once *before* capturing and, if it's flat zero, rebuilds the mic first (the user's words land on a live mic, not a corpse). A mid-dictation AudioContext interruption also freezes the analyser, so the watchdog alarms on a non-running context — and it's never auto-recovered: fail loud, redictate. And a dead/silent capture (peak 0) now fails *named* — "MIC PRODUCED NO SIGNAL" — never the misleading "no speech".
- **The noise gate — removed (2026-11-21).** It muted everything below a level threshold. In real use it made no difference open or closed, it recorded quiet iPhone speech as near-silence, and protecting word starts from it needed a 120 ms delay on every release. Removing it made every take ~120 ms faster and took away four sliders; the speaker filter handles other voices.
- **Too many settings.** The page had grown to 11 Options and 14 Advanced controls with a paragraph under each. Pared down (2026-11-21) to five Options, a short Advanced, and a separate Diagnostics; every retired toggle got a fixed value instead (auto-copy on, audio events off, auto gain off, high-pass 85 Hz, release tail 80 ms).
- **Clipboard writes need focus.** Both the modern API and the fallback fail when the tab is unfocused (behind Citrix/Cerner). I don't silently retry, with one sanctioned exception: a pending copy held with a red status and retried on refocus.

## Phone link

For setups where the desktop can't get a good mic. Pairing is named from both ends, because the same page runs on both devices: on the desktop, **📱 Pair a phone** shows a QR + 6-char code; on the phone, **🖥 Pair to a desktop** (on the main card, and in the top row of the phone screen) is where you type that code, or you just scan the QR. (The QR is generated on-page, never by an external service — the code routes to the room, and in shared mode the **access code guards it**: every session route requires the same access code the app uses, so a guessed 6-char code alone can neither read a note nor plant one on the clipboard). The phone joins, switches to its **phone layout**, and dictates in batch; the final text POSTs to the desktop, which writes the clipboard. While the phone is dictating, the desktop shows a live **"📱 Phone is recording…"** indicator (a pulsing dot that flips to "transcribing…" on release and clears when the text lands) so I know audio is flowing before the note arrives — it's a relayed, fire-and-forget cue, never load-bearing. Pairing survives reloads and app restarts on both sides until End session (desktop) / Leave (phone). The resilience machinery (heartbeat, reconnect, delivery queue, dedupe, focus-retry, and the AHK `/latest` poller for focus-free pasting) is detailed in `CLAUDE.md`. If you use the AHK poller against a shared-mode worker, set `PHONE_AUTH` (the access code) at the top of `hotkey.ahk` — the routes answer 401 without it.

### The phone layout — a notes list with a floating record button

The phone shows my dictations as notes (newest first), with a round record button floating at the bottom — hold to talk, or tap to start and tap to stop — instead of the old full-screen button. The screen colours and a frame at its edge still show the state at arm's length (red while recording, green when done, red on a failure), haptics mirror the beeps, and a timer with "Hearing you" sits beside ● REC.

- **Each take: 📤 Send to desktop, or 📥 Keep on phone** (paired only; remembered per device). *Send* is the phone as a microphone: every take goes straight to the desktop clipboard, and the desktop's append setting decides whether it extends the note there. *Keep* holds takes as notes on the phone until I send them.
- **➕ Add to this** on any note: my next take is added to the end of that note (one take, then it resets; the button reads ADD while it's armed). A note I've added to stays on the phone until I tap **📤 Send**. Send only ever delivers what the desktop doesn't have yet: just the new words if the desktop already has the start of the note, or the whole corrected note, *replacing* the desktop's copy, if I edited it after sending. That way the desktop's own append can never double the text.
- **Send a set as one note:** tick several notes (or tap "Select them" on the "N notes not sent yet" bar) and tap **📤 Send as one**. They go as ONE note, oldest first, because the desktop has one clipboard. That's for parts of one patient's note; notes for different patients go one at a time with their own Send. **Copy as one** does the same onto the phone's clipboard.
- **Every note says where it stands** when paired: *Not sent*, *⏳ Waiting to send* (queued; it sends itself when the desktop is back), *✓ Sent* (the desktop confirmed it), *New words not sent*, or *Edited since sent*. Notes the desktop doesn't have yet are never trimmed off the 100-note history.
- **Notes are editable in place** (tap to type; saved when I tap away), and **🗑 deletes** with a second tap.
- **Not paired, the phone is a notebook:** every take is its own note, and it is copied when the phone allows it. iPhone refuses to copy after the upload finishes, so instead of a red "copy FAILED" on every take the screen says **SAVED** and tells me to tap the note's **Copy** (a tap iPhone allows).

## Keyterms

Bias the transcription toward my vocabulary — drugs, anatomy, eponyms, names. Merged and deduped per dictation (my terms > checked presets), capped at 1000 terms under 50 chars. Edit the lists in `keyterms.js`; they reach every device on the next deploy. Keyterms add ~20% to cost, and over 100 terms every dictation bills as at least 20 s, so nothing rides by default: the always-on standard list was dropped on 2026-09-29 after WhisperInk testing showed Scribe v2 Medical doesn't need it. I check Wound care (145 terms) or ER shift (69) when the shift calls for it.

## Settings & storage

Everything is in `localStorage`, scoped to one browser profile / device / origin — desktop, phone, and an installed iOS PWA don't share. Set up each device I dictate from. The split I'm building toward: portable settings (keyterms, append/beep prefs) sync across devices; per-device tuning (hotkey, mic) stays local. Keyterm presets already reach every device because they ship in the code.

## Deploy

Push to `main` → Cloudflare Workers Builds deploys the worker `eleven` (`npx wrangler deploy` also works; the served HTML is `no-store`). Two ways to supply the key:

- **Shared mode:** set `ELEVENLABS_API_KEY` + `APP_PASSPHRASE`. Users enter only the passphrase; the Worker checks it in constant time and injects the key server-side — it never reaches the browser. Add `SONIOX_API_KEY`, `OPENAI_API_KEY` and/or `MISTRAL_API_KEY` to make Soniox, OpenAI gpt-transcribe and Mistral Voxtral Small Transcribe 3 selectable as the main service or the backup (shared mode only; a BYO key never uses them). Optional plain variable `SONIOX_FALLBACK_AFTER_MS` changes the wait before the backup is asked.
- **Bring your own key:** leave the passphrase unset; each user enters their own ElevenLabs key, stored per browser.

Set secrets in the Cloudflare dashboard (the local wrangler token can't write secrets): Workers & Pages → eleven → Settings → Variables and Secrets, type **Secret**, then Deploy — not under Build, which the running Worker never sees. `wrangler.toml` lists them and keeps dashboard variables across deploys (`keep_vars`). Install as an app from Chrome/Edge for a standalone window that keeps mic permission and stays usable shrunk to a sliver.

## Tuning the mic

There is no gate to tune. If takes come back thin or empty:

| Symptom | Fix |
|---|---|
| "VERY LOW MIC LEVEL", or a quiet trace | Raise **Mic boost** (Advanced), or bring the mic closer. iOS seeds a modest 3× boost on first launch |
| Other people's words in the note | Keep **Filter out other speakers** on (Options) and keep the mic close: it keeps the voice loudest at your mic |
| Background hum or hiss | Leave **Browser noise suppression** on (Advanced) |
| "MIC PRODUCED NO SIGNAL" / "MIC NOT CAPTURING" on the phone | A dead/silent mic (peak 0) — iOS handed back a live-looking but silent stream. The app **probes every press** and refuses to start recording into a provably silent mic (it rebuilds once, then fails loudly *before* you speak), and an **idle sampler** rebuilds a mic that dies between takes (watch the "Mic ✓ / ⚠" pill). Turn off **Low Power Mode**, stay in the app between takes, and try **Echo cancellation** off (Advanced) |

Constants at the top of the client script: `BATCH_UPLOAD_TIMEOUT_MS` (15000, the deadline *floor* — long takes extend it by 25% of the take, capped +60 s), `FLATLINE_RMS` (0.0008, the dead-mic threshold), `SPEECH_OPEN_RMS` / `SPEECH_CLOSE_RMS` (0.018 / 0.008, the read-only speech detector), `RELEASE_TAIL_MS` (80), `IOS_SEED_MIC_GAIN` (3) / `IOS_AUDIO_SEED_VERSION`, `HOTKEY_TAP_MS` (400, tap-vs-hold); the phone-link timings are in `CLAUDE.md`.

**Long dictations**: a multi-minute take can spend up to ~a minute in transcription — the app now waits proportionally instead of aborting at a flat 15 s (the AHK script's `CLIP_TIMEOUT` is sized to match). Every result is also checked against how much speech was actually heard: a transcript that stops well short of the end is flagged **"⚠ Transcript may be INCOMPLETE — covered M:SS of M:SS"** with a warn beep instead of a clean "Done!" — verify the end of the note before pasting.

## Roadmap

In priority order — #1 is the standing rule, never lose a dictation:

1. **Durability — done, now including a failed upload.** **A timed-out or failed transcription upload no longer costs the dictation** (2026-09): the recording is kept instead of being discarded with the text, and the take is offered for **retry** — a banner on the desktop card, a tappable chip on the phone screen — which survives a relaunch, so a clinician never redictates from memory because the network hiccuped. The upload **deadline is now size-aware as well as duration-aware** (the phone-link timeouts were the upload leg: the ElevenLabs request log showed zero failures and a 0.58 s median, i.e. the service never saw the aborted takes), and a failed take's timing row now records the **stage reached, error class and the deadline it blew** instead of a row of blanks. The dictation journal landed: each recorded chunk is mirrored to IndexedDB during capture (~30 min cap, and a capped recovery says so), and a take that the app died on (crash / kill / OOM before upload) is recovered on the next boot — a loud banner re-transcribes the saved audio and copies it. The **transcript-coverage guard** closes the last silent gap: a result that stops well short of the observed speech (service truncation or a mic that went quiet) is a loud "may be INCOMPLETE" warn — never a clean Done! — and logs a diagnosis to the failure ring (`scribe_v2_micfail_v9`). Long takes get a duration-scaled transcription deadline instead of the flat 15 s. **While ElevenLabs is slow, the app waits longer (2026-09-29):** on the 29th its speech-to-text took 3.3 s and 16.8 s for 3–4 s clips (normally under 1 s; our own network was 0.1–0.3 s) and the next takes timed out at ~19 s. Now, if one of the last few takes on a device timed out or waited more than 8 s at ElevenLabs, the minimum wait rises from 15 s to 45 s for the next half hour, and the countdown says "ElevenLabs has been slow". That includes the Retry of a timed-out take. **And the service is now a choice, with a backup (2026-09-29):** Options picks the main service (ElevenLabs, Soniox or OpenAI gpt-transcribe) and a backup; when the main one errors or hasn't answered after a few seconds, the Worker sends the same audio to the backup and the first good transcript wins (a late answer from the main service still wins if it comes first). Soniox's copy is deleted as soon as the take is decided; the status and the note say which service wrote it; both failing is still one loud failure. Soniox and OpenAI still have to go through the six clinical clips in WhisperInk before I rely on them for hard terms. **The backup now covers the streamed upload too (2026-11-10).** A take failed with a long wait and then nothing on the clipboard. The cause: while the audio streamed up during dictation, the Worker waited for ElevenLabs to accept each piece. When ElevenLabs stopped accepting audio without answering, the Worker stopped too, never reached the end of the take, and never asked the backup, so the take sat until the deadline and failed. The ordinary upload would have been rescued in about 4 s. The Worker now takes the audio at the browser's pace and starts the backup timer on release, whatever ElevenLabs has done. A backup that answers with no text no longer counts as a rescue (it used to stop ElevenLabs and turn a real take into "No speech detected"). Any crash in the app's finishing steps now ends as a loud failure with the recording kept for Retry, instead of a status stuck on "Transcribing…" with every later press silently queued. And `hotkey.ahk` keeps ⚠ FAILED / ⚠ TIMED OUT on its bar until the next press instead of flashing it for 2.5 s. **Every failed take now keeps its recording, not just the last one.** There was only one saved-recording slot: when a second take failed, it replaced the first take's recording, and a reload deleted all but the newest. So in a run of failures, redictating destroyed every earlier recording while each failure said "Your RECORDING was saved". Now each one waits its turn on the Retry banner (with its time, and how many more are waiting), survives a reload for 24 hours, and is retried or discarded on its own. **A long dictation survives a dead connection (2026-11-22).** A long take on a work remote desktop never reached the server at all (Cloudflare's logs held neither its start nor its upload); the app waited out its whole deadline, failed, and the saved recording was lost when the remote desktop was wiped. Now the app checks the server while you dictate and says so at once if it can't reach it (on the page and on the AutoHotkey bar: "● REC — NO CONNECTION"); an upload that went into a dead connection is sent again as soon as the server answers, and one stuck on a healthy connection gets a second copy beside it; and a failed take of 20 s or more is transcribed into the notes list by itself once the server is back — never onto the clipboard, since by then you may be in another chart — with "↺ RECOVERED — IN NOTES" on the bar. Every failed take also reports its timing to the cloud log, so a desktop that disappears still leaves the evidence. `hotkey.ahk` no longer cuts a CapsLock hold at 60 s (it stopped every long dictation at 1:00); the limit is 15 minutes, and hitting it is loud. **A click is no longer a failed dictation:** a take under a second with no words ends quietly ("Too short", no beep, a grey bar), while a real failure stays loud. *Next:* a UI to browse/replay the failure log and recovered audio.
2. **Phone-link delivery durability — done end-to-end, and the phone stands alone.** Dictating on the phone never needed the desktop, but it used to be *reported* as a failure whenever no desktop was listening: a red screen and a warn beep on every take, even though the note was transcribed, saved and queued. As of 2026-09 that is a **success** — a done beep and a status that says plainly it is queued and has not reached the desktop yet — while a desktop that *was* listening and then vanished still raises a single alarm. So you can dictate a whole shift on the phone with the desktop shut and push the notes over later. A note dictated while the desktop link was down can no longer be stranded: queued deliveries are code-bound and **survive Leave/rejoin** (re-linking with the same code delivers them immediately), a **"⏳ N waiting" chip** on both layouts makes the queue visible (tap to retry), and **"📤 Send to desktop"** (on the box, history rows, and every note on the phone) re-sends any past note on demand. Server-side, the room now **persists a ring of recent deliveries for 30 minutes** (survives Durable Object eviction, replayed on reconnect), the desktop **polls `/latest` as a fallback** whenever its WebSocket is down (a dead socket delays a note by at most ~a minute instead of losing it), and the phone screen shows a **"🖥 Desktop ✓ / not listening" pill** *before* you dictate (a positive check also delivers queued notes instantly).
3. **Phone-link security — access-code gate landed.** The session routes (`/deliver`, `/latest`, `/status`, the listener WebSocket) now require the shared access code whenever the worker has one configured, with **two-layer per-IP rate limiting** (Cloudflare's native global Workers rate-limit binding over a per-isolate backstop — both bound guess-scanning and DO-cost abuse, and the binding fails open so a plan without it still deploys) and a delivery size cap; a missing/wrong code is a loud, named failure on both surfaces, and the refused note stays queued. *Next:* end-to-end encryption of deliveries (key in the QR fragment, ciphertext-only relay) so patient text never rests readable on the room.
4. **Settings portability.** Sync the portable settings across devices while keeping per-device tuning local — export/import or passphrase-keyed server-side profiles.
5. **Phone UI — mic reliability after a resume, fixed.** The "mic gets stuck rebuilding" failure is gone (2026-09): an iOS resume fires three lifecycle events at once and each used to start its own microphone re-acquisition, leaving extra live streams that iOS starves, so the surviving one delivered pure silence and the app rebuilt in a loop until it was relaunched. Rebuilds are now serialized and superseded ones clean up after themselves; the between-takes self-heal is bounded and tells you to press the button instead of grinding; a mic that wakes a moment after a rebuild now records instead of being refused; and a pre-capture failure reports the level the probe actually measured rather than the previous take's. **The phone layout is now a notes list (2026-09-29):** the full-screen button took the whole phone, so the phone now shows its dictations as editable notes with a small floating record button. I can add a take to any earlier note, keep takes on the phone and send them later (one at a time, or several as one note), see which notes the desktop has, and copy or delete notes. An unpaired phone works as a notebook, with no red "copy FAILED" on every iPhone take. The take's timer and "Hearing you" light now show beside ● REC. *Next:* the waveform itself on the phone, and getting iPhone to copy automatically after the upload (a clipboard write started in the release tap might do it; it needs testing on a device). **Pairing and link-state UX pass (2026-09):** pairing is named from both ends ("📱 Pair a phone" beside "🖥 Pair to a desktop", the latter also in the phone screen's top row for a solo phone); a phone that leaves tells the desktop (its "Phone paired ✓" no longer outlives the phone); a dropped listener link that heals clears its red instead of leaving a stale FAILED; the phone is told in words when its desktop stops listening, with the next step; joining, leaving and a healed link never paint the screen DONE (DONE means a dictation reached the clipboard); the phone screen shows phone copy instead of the desktop's Ctrl+Space hint; Settings from the phone screen lands on Options; a permission-denied mic names the fix; and the batch-era copy (API key "(batch)", "engine", the retired filter explainer) is gone.
6. **Batch latency, mic accuracy, and the minimized-window recording cue.** Phases 0 and 1 of **`PERF_PLAN.md`** have **landed**: every take now records a per-stage latency breakdown to a per-device ring (with a `Server-Timing` split separating our transport from ElevenLabs inference, readable and exportable from Advanced); the whole window colours itself red while recording — plus tab title, favicon and taskbar badge — so a PWA shrunk beside Cerner on a machine with no speakers is readable at a glance; `hotkey.ahk` hands focus back to the window you dictated from (ending the alt-tab that cost more than the entire transcription pipeline) and shows an always-on-top state bar that works even when the app window is fully covered; and a gate look-ahead plus release tail stop the gate clipping the first and last words. Transcription now runs on **Scribe v2 Medical** (`scribe_v2_medical`, 2026-09), ElevenLabs' clinical fine-tune of Scribe v2 (drug names, anatomy, pathology): same request, same price, and every other setting is unchanged. **Upload while you dictate** (2026-09, Chrome/Edge, ported from WhisperInk; **off by default since 2026-11-22** — in real use it made no difference to speed and felt less stable, and a streamed take that hangs is never sent a second time, so the ordinary upload is the robust one): the request to ElevenLabs opens when you press and the audio streams up as you speak, so letting go waits only for the transcript. It is used only when the streamed audio matches the recording byte for byte; anything else falls back to the normal upload on its own, and the timing log names which path each take used. Verified in production on 2026-09-24: long dictations now land about 0.4 s after release however long they are (two 19-second takes: 391 and 422 ms), our own share of the wait is under 40 ms, and the rest is ElevenLabs' processing. Short takes are still being measured. *Next:* an A/B of short takes with streaming on vs off, then the mic levers (device picker, narrowband warning). **The gate is gone (2026-11-21)**: no level-based cut, no 120 ms look-ahead, so every release lands ~120 ms sooner (the capture tail is a fixed 80 ms). PCM upload is deprioritized: it would put a new audio processor in the recording path to save part of ElevenLabs' decode time. **Other voices in a noisy room (2026-10):** the speaker filter keeps the voice that is clearly loudest at the mic instead of the one that said the most, warns on any cut it can't confirm, and shows what it removed in History. Since 2026-11-21 it is on by default on every device, desktops included. *Next:* tune the 2× loudness threshold from the timing log (its `spkBy` / `spkRatio` / `spkCut` columns), and watch single-speaker desktop takes for any accuracy change now that diarization is the desktop default. **Mistake reports (2026-11-21):** any note can be reported in two taps, a missed word can be added to the vocabulary on the spot, and every report lands in one cloud log that can be queried directly, so misheard drug names can be collected and fixed. **A calmer, redesigned page (2026-11-21):** Options is down to five choices, Advanced holds machine tuning, Diagnostics holds measurement; the level meter and gate/link pills are gone; the look is a bedside monitor (one bold record band coloured by state, a sweeping trace, instrument type that ships with Windows and Apple, nothing downloaded).
